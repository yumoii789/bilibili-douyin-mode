# 刻意不做的、以及刻意做成别的样子的

> 这份文档用来回答一个反复出现的问题：「这里为什么不按 B站 那样做？」
> 每条都写明**依据**与**什么情况下我会改变决定** —— 免得以后（包括我自己）把它当成漏做。

## 一、不做的东西

| 不做 | 为什么 | 什么情况下会做 |
| --- | --- | --- |
| **「网页全屏」** | 沉浸流本来就是固定全视口，没有「第二个状态」可切；按 B站 的语义放上去就是个死按钮 | 若将来支持「在网页内嵌一块小播放器」的形态 |
| **双击画面全屏** | 双击必须让单击的暂停延迟 ~200ms 等第二击 —— 用一个**天天用**的操作去换一个**偶尔用**的（F 键/按钮已经有全屏） | 若用户明确要，并且接受单击延迟 |
| **网页面板里的「色彩调节」做成死按钮** | 项目原则：宁缺不做死按钮（亮度/对比度/饱和度都是真接 `filter` 的 ✓） | —— |
| **抖音侧样式硬编数值** | 抖音页面反爬（验证码中间页 / 混淆空壳），**没有可信证据源**；硬编等于拿想象当 1:1 | 用户提供抖音页的截图或 DOM 快照 |
| **多 durl 分片拼接** | 会引入一条与主流程并行的取流/拼接逻辑，收益（极少数老稿件）远小于风险 | 有明确用户诉求 |
| **写字幕（翻译/上传）** | 涉及 csrf 与账号风控面，且不是观看路径上的事 | —— |

## 二、刻意做成别的样子的（与 B站 网页不同，但有意为之）

| 我们的做法 | B站 网页的做法 | 依据 |
| --- | --- | --- |
| **滚轮 = 换屏** | 滚轮 = 调音量 | 沉浸流的**主操作**就是上下滑动（抖音式）；滚轮留给音量等于让主操作没有主键 |
| **↑↓ = 换屏** | ↑↓ = 音量 | 同上 |
| **←/→ = 快退快进 5 秒** | 同（B站 快捷键系统里有 `KeyF/KeyD/KeyM` 等按键枚举） | 通例；沉浸流里左右键本来是空的 |
| **F / M / D = 全屏 / 静音 / 弹幕开关** | B站 的快捷键**可自定义**，默认动作不完全一致 | 按通行约定接；文档里如实写成「按约定」，不谎称 1:1 |
| **侧栏顶部没有搜索框** | B站 网页没有侧栏 | 搜索框搬到**右上角**（客户端形态）；侧栏只放导航 |
| **用户区留在侧栏底部** | B站 网页在头部右上 | 实测 `right-entry` 有 **532px 宽**，顶栏塞不下（会把频道胶囊挤到 5 行）✗ |
| **频道右侧那组入口换行显示** | B站 排在同一行右侧 | 同一行会被我们固定在右上的搜索框压住；**换行显示**比「隐藏」好（隐藏＝静默删功能入口 ✗） |

## 三、测试里的取舍

| 做法 | 理由 |
| --- | --- |
| 假 DOM（`vm-test.mjs`）承载绝大部分逻辑断言 | 快、可重复、能造边界（回收/恢复、竞态、失败路径） |
| 但**真渲染与真按键必须另验** | 假 DOM 比真 DOM 薄：本项目已因夹具缺 API 被挡四次（`textContent` 子树、`style.setProperty`、沙箱 `getComputedStyle`…）；而键盘/全屏/音量这些**浏览器行为**它一样都验不了 |
| 桩环境不验「播放结果」 | 桩里视频没有真流，`play()` 起不来、`paused` 永远不变 → 要看「谁调用了 toggle」这类**与结果无关**的信号 |

## 四、已知的不一致（不是取舍，是还没做/验不了）

| 项 | 状态 |
| --- | --- |
| 视频页 / 番剧播放页的**观感** | JS 渲染页面，离线只能做 DOM 静态审计；观感待真机 |
| 登录态相关：不感兴趣是否真的影响推荐、`feedback/dislike` 为何 -400 | 需登录态真机确认 |
| 暗色下的配色「口味」 | 布局与可读性已离线验证，好不好看由用户定 |
