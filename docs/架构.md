# 架构说明

> 面向「要改这个扩展的人」。只写**代码事实**与**为什么这样做**，不写愿景。

## 1. 两个独立体：沉浸流 与 桌面版样式

它们**互不依赖**，各自一个开关（设置页里也是分开的）：

| | 沉浸流（`douyin-mode.js`） | 桌面版样式（`desktop-skin.js`） |
| --- | --- | --- |
| 做法 | JS 建一套自有的 DOM 覆盖层（`#bdm-root`） | **纯 CSS 重排** B站 自己的页面 |
| 入口 | 左下角 / 侧栏里的「刷B站」按钮 | `html.bdm-skin` 类名 |
| 关闭后 | 移除覆盖层，B站 页面毫发无损 | 去掉类名，页面立刻回到原样 |
| 为什么 | 覆盖层能精确控制滑动手感与回收 | 页面结构由 B站 维护，**不重写它的 DOM** 才安全、可逆 |

两者的共同前提：**不动 B站 的 DOM 骨架**（除沉浸流自己建的覆盖层）。B站 是 SPA，抢它的渲染方向盘风险远高于收益。

## 2. 文件与职责

```
manifest.json          MV3；内容脚本按顺序注入（settings → desktop-skin → api → ui → player → douyin-mode）
src/content/
  settings.js          设置读写 + 默认值 + 跨标签同步（chrome.storage.onChanged → bdm:settings-changed 事件）
  desktop-skin.js      桌面版样式的开关：给 <html> 加 bdm-skin；量频道条高度写 --bdm-channel-h
  api.js               B站 接口封装：字段形状、错误码翻译、wbi 签名自愈、后台中转兜底
  ui.js                沉浸流的 UI 骨架（buildSlide 返回一屏的所有节点引用）与设置面板
  player.js            播放器：DASH 双轨、档位、弹幕调度、画面效果（比例/旋转/镜像/色彩）、音量均衡
  douyin-mode.js       沉浸流的编排：信息流、滑动、回收/恢复、各种面板、右键菜单、诊断串
src/options, src/popup 设置页与弹窗（纯静态 HTML + 一个脚本，无框架）
src/background/        service worker：右键下载菜单 + 字幕中转（唯一需要跨域的地方）
test/                  Node 测试（3 套件）+ 真渲染预览页（浏览器里打开，页面自己打印检查结果）
```

## 3. 沉浸流的关键机制

- **一屏一个 `rec`**：`{ item, slide, player, loaded, failed, cmts, qn, ... }`。`slides[]` 与 `items[]` 索引一一对应（插入/移除都必须维持这个不变量）。
- **回收与恢复**：远端屏的媒体会被释放（`bdm-released`），划回来时**重新挂播放器**。这里踩过最大的坑是「恢复时清空了 `videoArea`」→ 黑屏；因此恢复路径必须**幂等**（`applyStream` 重复调用安全）。
- **滑动 = 原生滚动**：靠 `scrollTop` 定屏，所以「划不动」类问题先看 `diag()` 的数字（滚动高度/子节点数/当前屏）。
- **迟到的异步写入**：换屏/退出后，仍在飞的请求（取流、在线人数、评论）必须有守卫，否则会写进已拆的屏。守卫模式统一是 `if (!active || rec.gone) return;`。
- **发弹幕/点赞/三连**：全部有在途锁（`dmSending` / `beginAct`），防连点重复提交（三连会多扣币，这是真缺陷）。

## 4. 桌面版样式（接管层）的规则

- 侧栏 = `.bili-header__bar` 固定到左侧 200px；**只有页面真有这个容器时**才给 `body` 让位（`:has()` 守住，老浏览器有 `@supports` 兜底）
- 顶部 = 把 `.bili-header` 改成竖排并用 `order` 把 `.bili-header__channel` 排到 `banner` **之前**（B站 的 DOM 顺序是反的）；频道条 `fixed` 吸顶（`sticky` 试过，**粘性范围被父容器夹住，吸不住**）
- 内容 = banner 限高圆角 + B站 自己的卡片网格（实测它本来就是 16:9 / 4 列 / 15px 标题，**不需要改**）
- 隐藏 = 网页 footer、顶部广告位、装饰分隔线、频道右侧那组网页特有入口

## 5. 测试策略（以及为什么值这么多代码）

| 套件 | 覆盖 |
| --- | --- |
| `preflight.mjs` | 「装得起来吗」：manifest/引用/语法/i18n/版本一致/CI 配置 |
| `vm-test.mjs` | 逻辑：假 DOM 里跑真实内容脚本，18+ 组断言（状态循环、边界、失败路径、竞态） |
| `pages-test.mjs` | 扩展自己的页面与纯函数（设置页/弹窗/皮肤 CSS 的文本级守卫） |
| `test/*-preview.html` | **真渲染**：几何、皮肤三态、CSS 泄漏、真浏览器交互/长会话/全屏 |

**最重要的一条经验**：假 DOM 比真 DOM 薄，**每缺一个 API，真实代码就被挡在门外**（本项目先后补过 `textContent` 子树语义、`style.setProperty/removeProperty`、沙箱 `getComputedStyle`）。所以测试里出现「某个方法 is not a function」时，**先怀疑夹具，不要先怀疑产品代码**。

同理：**「规则生效了」不等于「算出来的值是对的」**（侧栏图标白底白图那次的教训），量东西要量**目标元素自己**的计算值。

## 6. 已知边界

> 「刻意不做的」与「刻意做成别的样子的」见 `docs/取舍.md`（每条都带依据）。


- 视频页 / 番剧索引 / 排行榜 / 专栏：**JS 渲染**，抓下来的 HTML 没有头部容器 → 离线只能做 DOM 静态审计，观感必须真机确认
- 抖音侧样式 1:1：抖音页面有反爬（验证码中间页/混淆空壳），没有可信证据源 → **不硬编数值**
- 「网页全屏」刻意不做：固定视口下没有第二个状态，宁缺不做死按钮
